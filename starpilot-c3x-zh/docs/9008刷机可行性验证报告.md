### 5. 可软件进入 9008，无需拆机


```bash

sudo reboot
```

重启后设备以 `05c6:9008` 枚举，Windows 上被 SkyGMFlasher 识别为 COM 口。

> ⚠️ 执行后设备**必须**接上电脑用工具刷写才能恢复，不能自行开机。请在一切就绪后再执行。

- 来源设备的 `original_device_init_seconds: 394.9`（约 6.6 分钟）

所以**用户区密钥不会跨设备复用** ✅

8. 等待完成（17.5 GB，USB 2.0 约 50–90 分钟，USB 3.0 约 15–25 分钟）
9. 完成后手动点 **重启**

> 不要中途断电、不要拔线、不要关工具。

## 四、风险清单

### 🔴 高风险：私有包携带来源设备的硬件身份

`raw_plan.json` 明确标注：

```json
"classification": "PRIVATE_FULL_DEVICE_RECOVERY_NOT_PUBLIC_DISTRIBUTION",
"wifi_ssh": "Source-device sealed envelopes; NOT a cross-device distribution package"
```

刷入后会覆盖本机以下分区，**内容来自另一台设备**：

| 分区 | 内容 | 影响 |
|---|---|---|
| `persist` | 相机/IMU/传感器工厂校准 | **校准不匹配**，ADAS 精度可能下降 |
| `modemst1/2`、`fsg` | modem NV、IMEI | 网络标识变成来源设备的 |
| `devinfo` | 设备标识 | 序列号等信息被替换 |
| `keystore`、`storsec_a/b`、`cmnlib*`、`keymaster*` | TEE 绑定密钥 | 与来源设备的 TEE 绑定 |
| `wifi_ssh`（封存在 system_a 里）| 来源设备的 Wi-Fi/SSH 凭据 | **本机无法解密**，需重新配网 |

**后果**：

- 本机原有校准/密钥被**永久覆盖**（除非事先备份 `persist`、`modemst*`、`fsg`、`devinfo`）
- 无法从本机恢复出厂校准
- 若两台设备同时在用，可能出现身份混淆

### 🟡 中风险：工具与包都未做整包实机验收

包内 `full_test` 字段自述：

```
full_package_entity_flash_tested: False
cross_device_compatibility_tested: False
device_written: False
```

工具 README 也写："单测及模拟传输不等于新设备实刷或启动验收"。

**含义**：这是**工程预览版**，不是已验收的量产流程。第一次刷建议在**可放弃的测试机**上做。

### 🟡 中风险：不可中断

- 刷写阶段断电 → 分区表损坏，需重刷
- 首次开机 userdata 初始化断电 → 用"继续未完成初始化"，但反复失败需人工处理

### 🟢 可控点

- userdata 全新加密，不复制来源密钥 ✅
- 引导哈希强制登记校验，不会误用错误 Firehose ✅
- 工具不执行包内脚本（`package_verify` 只读 XML/JSON/二进制）✅
- 不做 RPMB/eFuse 写入 ✅

## 五、建议

### 如果你的目的是「给新设备做批量初始化」

**可行，但强烈建议换一个干净包**：

- 用官方 comma AGNOS 恢复包（不含私有 NV/校准），或
- 从**你自己**的第一台设备做私有包，后续所有设备都刷它（至少身份来源可控），或
- 让 skyGM 作者提供一个**脱敏外发包**（去掉 persist/modemst/fsg/devinfo/wifi_ssh 的版本）

### 如果你的目的是「修复当前这台变砖的设备」

**这正是工具的设计用途，可行性最高**。但要接受校准身份被替换。

### 如果设备现在工作正常

**不建议刷**。当前设备已经跑着 AGNOS 19.9 + StarPilot + 我们的汉化，刷 RC10 会把系统回退到包里的版本，然后把上面所有工作重做一遍。

给其他设备装我们的补丁包，**只需要**：

```bash
cd /tmp
git clone <你的仓库>/starpilot-c3x-zh.git
cd starpilot-c3x-zh
sudo bash install.sh
```

前提是那台设备已经跑着兼容的 StarPilot（基线 `2589caad`）。
